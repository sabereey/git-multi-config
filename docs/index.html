Multi-account Git, solved

One command sets up company and personal Git on one machine. The directory decides the identity.

Company work goes to your company Git server with your company email and company SSH key. Side projects go to GitHub with your personal identity. You never switch anything by hand.

It also audits repositories that already have the wrong local config, and can install a pre-commit guard that refuses to commit with an unregistered email.

install.sh 
curl -fsSL https://raw.githubusercontent.com/sabereey/git-multi-config/main/install.sh | bash

The problem

Two accounts on one laptop cause three classic accidents.

git commit

A commit authored with the wrong email

Your company commit carries your personal address, or a public repo shows your work identity. It is recoverable, but only if you notice — and nobody notices.

git clone

Permission denied (publickey)

SSH tries your keys in sequence and offers the wrong one. The fix people reach for is reordering ~/.ssh/config, which breaks the other repository.

git config --local

Thirty old repositories, all wrong

They were cloned before you cared. Each one carries a stale user.email, and fixing them by hand is an afternoon of cd and copy-paste.

How it works

Answer eight questions once. Everything after that is automatic and inspectable.

git-multi-config init
$ git-multi-config init

  Company server   git.corp.example.com
  Company identity Corp User <dev@corp.example.com>
  Company dirs     ~/work
  Personal server  github.com
  Personal identity you <you@example.com>
  Personal dirs    ~/personal
  Default identity personal
  Commit guard     yes

[ ok ] wrote ~/.ssh/config
[ ok ] wrote ~/.gitconfig-company
[ ok ] wrote ~/.gitconfig-personal
[ ok ] wrote includeIf rules
[ ok ] installed pre-commit guard
~/.config/git-multi-config/includeif.conf
# generated — do not edit by hand

[includeIf "gitdir:~/work/"]
        path = ~/.gitconfig-company

[includeIf "gitdir:~/personal/"]
        path = ~/.gitconfig-personal

# git 2.36+: also match by remote URL,
# so company repos cloned elsewhere still
# get the company identity
[includeIf "hasconfig:remote.*.url:git@git.corp.example.com:**"]
        path = ~/.gitconfig-company

Why core.sshCommand, not just SSH aliases

Aliases only work if you remember to use them. Each profile also sets core.sshCommand, so the correct key is forced inside the directory — even when a remote points straight at the host.

Why two rules per directory

Git matches gitdir: against physical paths. On macOS /tmp and /var are symlinks, so a single logical rule silently fails to match. Both forms are written.

What you get

A single bash script. No runtime, no daemon, nothing to keep running.

  • Directory-based switching of user.name, user.email and signing key
  • Right SSH key per directory via core.sshCommand
  • audit finds identity and remote mismatches; audit --fix repairs them
  • Commit guard refuses to commit with an email you never registered
  • doctor checks git version, files, key permissions, hooks and SSH login
  • Idempotent — re-running never duplicates a managed block
  • Reversible — uninstall removes everything and restores your previous hooks path
  • Bilingual interface and docs, English and 简体中文

FAQ

The questions people actually ask.

How do I use a different Git identity and SSH key for company and personal repositories?

Use Git conditional includes. Map each directory to a profile file with includeIf "gitdir:<dir>/", so Git loads a different user.name and user.email depending on where the repository lives, and force the matching key per profile with core.sshCommand. git-multi-config init generates all of it from one command and audits repositories you already have.

Why does git config user.email still show the wrong address in a folder under my personal directory?

That folder is almost certainly not a repository. A gitdir: condition is only evaluated once Git has found a repository — the pattern is matched against the location of the .git directory — so in a plain folder nothing matches and you see the global default. Check from inside a real one:

cd ~/Documents/some-project
git config --show-origin --get-all user.email
#   file:~/.gitconfig            <your default>
#   file:~/.gitconfig-personal   you@example.com   ← conditional include applied

Both my accounts live on github.com. Does that work?

Yes. The company entry gets a distinct alias such as github.com-work and the personal side gets github.com-personal. Per-profile core.sshCommand still forces the correct key inside each directory, and audit --fix rewrites remotes that bypass the alias.

What about repositories cloned outside the managed directories?

They keep the default identity you selected. On Git 2.36+ the hasconfig:remote.*.url: rules also match by remote URL, so a company repository cloned elsewhere still picks up the company identity.

Any runtime dependencies?

No. One bash script, working with the bash 3.2 that ships on macOS. No Node, Python, Go, jq or background daemon. Git 2.13+ is required; Git 2.36+ additionally enables the remote-URL rules.
