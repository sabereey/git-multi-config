多账号 Git，一次解决

一条命令，在公司电脑上配好公司与个人的 Git 多账号。目录决定身份。

公司项目走公司私服，用公司邮箱和公司 SSH 密钥； 个人项目走 GitHub，用个人身份。整个过程不需要你手动切换任何东西。

它还能审计你已经存在的、本地配置写错的仓库，并可选装一个提交前钩子， 拒绝用未登记的邮箱提交。

install.sh 
curl -fsSL https://raw.githubusercontent.com/sabereey/git-multi-config/main/install.sh | bash

要解决的问题

一台电脑上两个账号，会引发三类经典事故。

git commit

提交带上了错误的邮箱

公司提交里混进了你的个人邮箱，或者公开仓库暴露了你的工作身份。事后能改， 但前提是你发现了 —— 而通常没人发现。

git clone

Permission denied (publickey)

SSH 按顺序试密钥，把错误的那把递了上去。大家常用的办法是调换 ~/.ssh/config 顺序，结果把另一边的仓库弄坏了。

git config --local

三十个老仓库，全是错的

它们是在你还不在意这件事的时候克隆的，每个都带着过期的 user.email。手工一个个修，就是一个下午的 cd 加复制粘贴。

实现原理

回答八个问题，之后全部自动、且随时可查。

git-multi-config init
$ git-multi-config init

  公司服务器     git.corp.example.com
  公司身份       Corp User <dev@corp.example.com>
  公司目录       ~/work
  个人域名       github.com
  个人身份       you <you@example.com>
  个人目录       ~/personal
  默认身份       个人
  提交拦截钩子   是

[ ok ] 已写入 ~/.ssh/config
[ ok ] 已写入 ~/.gitconfig-company
[ ok ] 已写入 ~/.gitconfig-personal
[ ok ] 已写入 includeIf 规则
[ ok ] 已安装提交前钩子
~/.config/git-multi-config/includeif.conf
# 生成文件，请勿手工编辑

[includeIf "gitdir:~/work/"]
        path = ~/.gitconfig-company

[includeIf "gitdir:~/personal/"]
        path = ~/.gitconfig-personal

# git 2.36+ 起，还会按 remote 地址匹配，
# 因此在别处克隆的公司仓库同样
# 会用到公司身份
[includeIf "hasconfig:remote.*.url:git@git.corp.example.com:**"]
        path = ~/.gitconfig-company

为什么用 core.sshCommand，而不只是 SSH 别名

别名只有在你记得用它时才有效。每个身份同时设置 core.sshCommand， 于是目录内始终强制使用正确的密钥 —— 即使 remote 直接指向主机名也一样。

为什么每个目录写两条规则

Git 是把 gitdir: 和物理路径做匹配的。macOS 上 /tmp、 /var 都是软链，只写逻辑路径会静默失配，所以两种形式都写。

你得到的

一个 bash 脚本。没有运行时、没有常驻进程、没有需要你维护的东西。

  • 按目录切换 user.name、user.email 与签名密钥
  • 每个目录用正确的 SSH 密钥，靠 core.sshCommand 强制生效
  • audit 找出身份与 remote 错配，audit --fix 直接修复
  • 提交拦截钩子拒绝用未登记的邮箱提交
  • doctor 检查 git 版本、文件、密钥权限、钩子与 SSH 登录
  • 幂等 —— 重复执行不会产生重复的管理块
  • 可回滚 —— uninstall 清干净，并还原你之前的 hooksPath
  • 中英双语界面与文档

命令

六个子命令，以及一套在临时 $HOME 里跑的测试。

命令作用
init交互式配置向导。支持 --from-file，用于非交互地批量配置机器。
audit [--fix]扫描受管目录下的所有仓库，找出身份或 remote 错配。发现问题时退出码非零，可直接当 CI 门禁用。
list打印当前配置与解析后的文件路径。
doctor [--ssh]检查 git 版本、规则是否挂载、密钥权限、钩子健康度，可选测试 SSH 认证。
uninstall [--restore]移除所有管理块，并还原之前的 core.hooksPath。
help用法与选项说明，中英双语。

常见问题

大家真正会问的那几个。

同一台电脑上，怎样让公司仓库和个人仓库用不同的 Git 身份和 SSH 密钥？

用 Git 的条件包含。给每个目录写一条 includeIf "gitdir:<目录>/"， 让 Git 按仓库所在位置加载不同的 user.name 与 user.email； 再用 core.sshCommand 为每个身份强制指定对应的 SSH 密钥。 git-multi-config init 一条命令生成全部配置，并审计你已有的仓库。

为什么个人目录下的某个文件夹里 git config user.email 还是打印公司邮箱？

那个文件夹几乎可以肯定不是仓库。gitdir: 条件只有在 Git 找到仓库之后 才会被求值 —— 匹配对象是 .git 目录所在的位置 —— 所以在普通文件夹里没有任何 条件命中，你看到的是全局默认身份。请进到真正的仓库里确认：

cd ~/Documents/some-project
git config --show-origin --get-all user.email
#   file:~/.gitconfig            <全局默认>
#   file:~/.gitconfig-personal   you@example.com   ← 条件包含生效了

公司和个人两个账号都在 github.com 上，可以吗？

可以。公司条目会分到独立别名（例如 github.com-work），个人侧是 github.com-personal。每个身份的 core.sshCommand 仍然保证目录内 使用正确密钥，audit --fix 还能把绕过别名的 remote 改回来。

clone 到受管目录之外的仓库会怎样？

它们使用你设定的默认身份。在 git 2.36+ 上， hasconfig:remote.*.url: 规则还会按 remote 地址匹配，所以在别处克隆的公司仓库 依然会自动使用公司身份。

有运行时依赖吗？

没有。一个 bash 脚本，macOS 自带的 bash 3.2 即可运行。不需要 Node、Python、Go、 jq，也没有常驻进程。git 2.13+ 即可；git 2.36+ 还能启用 remote 地址规则。
